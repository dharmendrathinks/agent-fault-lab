# Agent Fault Lab v0.4.0 — Evaluation and runtime transfer

Stable release dated 2026-09-08, explicitly authorized by the maintainer. Phase 4
adds repeated comparisons, independent evaluator audits and a real LangGraph
runtime integration. This is a full release, with prerelease disabled.

## Included

- **[M14](../milestones/M14.md):** frozen study manifests, shuffled scenario blocks,
  alternating policy order, three repetitions by default, a 30-minute active-time
  budget, ordinary workflow companions and preserved failed/interrupted slots.
  Reports separate actual storage, execution, claim validity, scanner findings,
  authorization, duration and usage. Conditional intervals disclose their limits.
- **[M15](../milestones/M15.md):** 43 independently authored SQL fixtures and twelve
  deliberately defective graders executed in disposable package copies. Harness
  errors never count as defect detection. Existing production grades are unchanged.
- **[M16](../milestones/M16.md):** LangGraph 1.2.11 in a separately locked Python
  3.12 environment. A real model/tools/terminal graph controls its own loop, sharing
  individual model/tool contracts and the independent evaluator with native runs.
  Four matched cases support bounded runs and a 24-run repeated comparison.
- Bounded local semantic SkillSpector transport with strict request, time and
  evidence limits; failed feasibility probes leave comparisons incomplete.
- Updated CLI, documentation, installed-wheel checks and real-graph CI coverage.

## Evidence and limitations

Local validation passed 850 tests with one gated live-test skip, lint, strict
typing across 97 files, locked dependencies, builds and installed-wheel checks.
Real static scanning passed M11 and 26 context runs. Real graph checks covered four
paired scenarios and six protocol, budget and provider-failure cases while
forbidding delegation to the native loop.

The independent audit passed all 43 baseline fixtures and detected all twelve
intended defects without harness errors. The final offline runtime study sealed
24/24 observations: both runtimes completed the approved and refreshed-title cases,
and enforced permissions against rejected and injected writes. All child reports
rebuild from captured evidence. These are actual graph/scanner/SQLite executions
with scripted model responses, not live-model effectiveness measurements.

Both initial local semantic probes timed out on the first physical request at
60 seconds, yielding no complete classification. See the
[probe evidence](../milestones/M14-semantic-probes.md). No limits or model were
changed to obtain a successful result. The full M14 live agent/scanner comparisons,
M16 live runtime comparison and pending learning reviews remain explicit follow-ups.
No framework winner or general scanner-accuracy claim is supported.

Manual approval, child resume and crash/restart parity are unsupported for the
runtime transfer. Study resume continues only unstarted slots. Workers inherit
the study lock and remaining deadline, with a maximum 450-second runtime timer.
Termination cannot undo committed writes or guarantee that Ollama stops a submitted
generation. Python socket restrictions are not an operating-system sandbox.

## Installation

From the repository root with Python 3.12 and uv:

```sh
git checkout v0.4.0
uv sync --locked --all-groups
mkdir -p runs
uv run --offline --no-sync aflab evaluator audit --output runs/my-audit
make scanner-setup runtime-setup
uv run --offline --no-sync aflab runtime doctor langgraph
uv run --offline --no-sync aflab runtime run langgraph approved --offline --output runs/my-graph
uv run --offline --no-sync aflab report runs/my-graph --check
```

Setup may download locked Python packages; the examples use no inference. Use
new output directories. The source archive includes both integration locks and
setup files. The wheel contains the adapters but does not bundle SkillSpector,
LangGraph, model weights, local environments or private run databases. Use the
matching checkout/source archive for runtime integration setup.

Package/source/lock fingerprints participate in resume compatibility. Resume old
runs with their original environment; saved reports remain readable. No changed-
source journal migration is implied. The approved local model and root runtime
dependencies are unchanged.
