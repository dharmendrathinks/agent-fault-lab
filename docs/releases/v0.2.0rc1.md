# Agent Fault Lab v0.2.0rc1 — Phase 2 release candidate

Release candidate dated 2026-09-07. This prerelease adds tool-execution reliability
experiments for review. v0.1.0 remains the latest stable release. M08/M09 learning
checkpoints and M10's independent diagnostic review are still pending; publication
does not mark Phase 2 fully accepted.

## Included

- **M06 — Tool contracts:** strict versioned result envelopes, malformed and
  semantically invalid responses, raw-response evidence and paired validation policies.
- **M07 — Retry safety:** failures before writes versus lost replies after commit,
  bounded retries, atomic operation-ID deduplication and independent duplicate checks.
- **M08 — Delays and limits:** owned worker processes, transient recovery,
  deadline observation, terminate/kill cleanup and separate side-effect accounting.
- **M09 — Restart recovery:** durable conversation checkpoints, persisted budgets,
  run ownership, protected replay and repeatable process-crash experiments.
- **M10 — Diagnosis:** read-only Markdown/JSON failure timelines, durable event
  ordering, source references and explicit evidence gaps.

The original dropped-write comparison and saved-report readers remain available.
The candidate adds `aflab reliability`, `aflab resume` and `aflab diagnose`.
See the [README](../../README.md) for an offline quickstart and the
[artifact guide](../artifacts.md) for saved evidence formats.

## Evidence and interpretation

Local verification recorded 440 passing offline tests and one gated live test
skipped, plus lint, strict typing, locked dependencies and wheel/source builds.
The installed-wheel smoke exercises comparisons, report readers, process execution,
finalized resume and diagnosis outside the checkout with Python sockets blocked.
[Hosted Ubuntu/macOS CI](https://github.com/dharmendrathinks/agent-fault-lab/actions/runs/34132647062)
passed on release commit `c95ebe0` before publication. Both downloaded package
assets match their SHA-256 checksums and original bytes. The complete publication
record is in [PROGRESS.md](../../PROGRESS.md).

The bounded local-model smokes retain unfavorable results:

- [M06](../milestones/M06-live-smoke.md): four runs, including an invalid terminal
  report and wrong-ID claims despite completed tasks.
- [M07](../milestones/M07-live-smoke.md): six runs; a lost reply produced two tasks
  with unprotected retry and one with operation-ID replay. All six completion
  claims used incorrect IDs.
- [M08](../milestones/M08-live-smoke.md): six runs; four stored tasks and two absent
  tasks. Three wrong-ID completions and one false non-completion were contradicted.
- [M09](../milestones/M09-live-smoke.md): four uninterrupted/resumed runs, each with
  one task; all four completion claims used incorrect IDs. Both crash barriers
  were reached, and after-commit recovery replayed the original operation once.

These small smokes demonstrate observed execution behavior, not statistical model
reliability. Raw live bundles remain local; checked-in notes record their provenance.
Scripted tests demonstrate the machinery, not live-model behavior. No additional
inference was performed for release publication.

## Guarantees and limits

- Operation-ID replay prevents another task effect for the same retained key and
  matching payload in this SQLite workflow. Different model calls have different
  operation identities. This is not an end-to-end exactly-once guarantee.
- A deadline does not undo a committed write. Observation waits for the finite late
  result; termination confirms worker exit before grading or another dispatch.
- Resume requires a compatible persisted process run, its original configuration
  and source/package fingerprint, retained storage and matching live-model identity.
  Unknown interrupted elapsed time charges the full reservation. Legacy runs are
  readable but cannot be resumed.
- Diagnosis explains saved evidence without fresh evaluation or inference. Missing
  evidence stays unknown. An independent engineer's diagnostic review is pending.
- Python 3.12 and macOS/Linux process control are required. Windows, distributed
  queues, arbitrary remote tools, power-loss recovery and Phase 3 are outside scope.

See [known limitations](../known-limitations.md) and the
[M10 review worksheet](../milestones/M10.md).

## Packages

The GitHub prerelease provides `agent_fault_lab-0.2.0rc1-py3-none-any.whl`,
`agent_fault_lab-0.2.0rc1.tar.gz` and `SHA256SUMS`. Download all three into one
directory and run `shasum -a 256 -c SHA256SUMS` to verify the package bytes.
Checksums do not authenticate experimental evidence.

For locked development setup, check out `v0.2.0rc1` and follow the README.
No package is published to PyPI, and no model weights or private run data are bundled.
