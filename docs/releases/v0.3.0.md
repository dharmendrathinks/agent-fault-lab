# Agent Fault Lab v0.3.0 — Agent boundaries and state

Stable release dated 2026-09-07, authorized by the maintainer after the local
release-preparation handoff. This release adds the implemented Phase 3 experiments
with offline and real static-scanner evidence. Phase 3 local-model smoke and
M12/M13 learning acceptance remain disclosed follow-ups, not completed validation.

## Included

- **[M11](../milestones/M11.md):** real static SkillSpector scanning before content
  admission, operation-specific approvals, explicit approve/reject/resume commands,
  and atomic task/grant/receipt writes with independent authorization evaluation.
- **[M12](../milestones/M12.md):** four synthetic attack/benign pairs on skill,
  task and tool-response surfaces. Crossed scanner/permission policies separate
  detection, delivery, unsafe attempts, actual effects and legitimate work blocked.
- **[M13](../milestones/M13.md):** stale requests, changed policy, stale approvals,
  poisoned notes and shortened history. Cached/authoritative-refresh comparisons
  preserve exact supplied context and independently inspect current task state.
- Versioned boundary journals, bounded budgets across restart, read-only reports
  and diagnostic timelines. Original dropped-write and Phase 2 readers remain.

## Evidence and interpretation

The local 0.3.0 checks passed 773 offline tests with one gated live
test skipped, strict typing, lint/format, locked dependency checks, package builds
and isolated installed-wheel verification. Six additional scripted context runs
used the installed wheel and real scanner outside the checkout. Archive contents
and both extracted source locks were also checked. Final verification is recorded in
[PROGRESS.md](../../PROGRESS.md).

The annotated release tag points to `ff45853`.
[Ubuntu/macOS CI run 34149280979](https://github.com/dharmendrathinks/agent-fault-lab/actions/runs/34149280979)
passed both complete jobs, including real-scanner acceptance. GitHub confirms
stable/latest publication with prerelease disabled, and downloaded release assets
match their SHA-256 checksums.

Hosted macOS testing exposed a cleanup error when only zombie process-group entries
remained. The release fixes that case with bounded process-state inspection while
preserving permission failures for live or uninspectable groups. Ten additional
regressions cover the distinction; the real descendant/late-write test remains.

The real static integration exercised M11 approvals and 26 M12/M13 context runs.
SkillSpector classified three of four synthetic attack skill fixtures as SAFE;
it blocked the concealed-instruction fixture and admitted all four benign fixtures.
Permission enforcement prevented the scripted unauthorized effects, while audit
reproduced them. All five M13 cases were scanned SAFE. Authoritative refresh avoided
the scripted stale attempts; changed-policy safely stopped without completing the
original task. See the [static smoke evidence](../milestones/Phase3-static-smoke.md).

These are real scanner/SQLite observations with scripted agents and synthetic
approval decisions. They do not measure live-model reliability or general scanner
accuracy. A SAFE result does not establish that a skill is harmless or authorize
a write. Missing claims, unexercised injections and unknown storage remain visible.

## Installation and compatibility

Use Python 3.12 on macOS or Linux, starting from the repository root:

```sh
git checkout v0.3.0
uv sync --locked --all-groups
make scanner-setup
uv run --offline --no-sync aflab scanner doctor
mkdir -p runs
uv run --offline --no-sync aflab boundaries compare injection-override --surface tool --offline --output runs/phase3-injection
uv run --offline --no-sync aflab report runs/phase3-injection --check
```

Setup downloads locked packages; the example then runs static scanning and scripted
agents offline. Each experiment requires a fresh output directory.

SkillSpector 2.11.1 is pinned to commit
`704bc9544260c2f41222dc0f92982521709496ab` in a separate Python environment and lock.
The source archive includes its setup files and inert fixtures. The lab wheel
does not bundle the scanner, its dependencies, model weights or raw run data.
For an installed wheel, install the separate scanner from the source archive or
matching checkout and supply `--scanner-python` to `boundaries run/compare`.
See the [integration instructions](../../integrations/skillspector/README.md).

The package version participates in resume compatibility. Runs created by an older
checkout, including unreleased Phase 3 runs labeled 0.2.0, must resume with their
original source and environment. Existing saved reports and diagnostics remain
readable; no journal migration or changed-source resume is implied.

The scanner subprocess is bounded and blocks Python sockets but is not an OS
sandbox. Approval assumes a trusted local operator/filesystem; synthetic controller
decisions are not human consent. No third-party skill code or semantic scanner
inference is executed. See [known limitations](../known-limitations.md).

## Release gates

Publication requires PR Ready, local package checks and hosted Ubuntu/macOS
CI on the tagged commit, including real-scanner acceptance on both platforms.
The release commit, CI run and remote asset verification are recorded in
[PROGRESS.md](../../PROGRESS.md). No prerelease tag is substituted for v0.3.0.

The maintainer's publication request supersedes the earlier ordering that held
publication for learning acceptance and live smoke. Those remain follow-ups:
record M12/M13 learning acceptance and, with separate inference opt-in, run the
planned 16 local-model cases (four M11, eight M12, four M13) after checkpoint
identity verification. Publication does not mark these milestones fully complete.
