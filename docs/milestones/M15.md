# M15 — Evaluator robustness

Available in v0.4.0. Learning acceptance remains
pending. The question is whether our grader rejects wrong behavior while accepting
valid alternatives; the grader itself can produce false failures or miss defects.

## Run the audit

```sh
mkdir -p runs
uv run --offline --no-sync aflab evaluator audit --output runs/evaluator-audit
uv run --offline --no-sync aflab report runs/evaluator-audit --check
```

Use a new output directory. No scanner, model, network or user database is needed.
The command seeds 43 fresh SQLite fixtures directly through SQL. Expectations are
authored from the contract, without calling task tools or copying grader output.
The baseline must pass before any deliberate defect runs.

## What is checked

- Missing, wrong and duplicate tasks; exact whitespace and Unicode; alternate IDs.
- Strict whole-response claims, absent claims and committed writes after an
  execution failure. Storage outcome stays separate from execution and reporting.
- Missing, rejected, premature, expired, stale and wrongly scoped write grants.
  An authorized historical write remains authorized after its grant expires.
- Idempotent replay, unchanged reference rows, changed or missing seeds,
  uninspectable task/authorization data and an unexercised configured scenario.
- Identifier renaming, row order and irrelevant/equivalent histories preserve
  contract outcomes. Policy revocation can make safe termination appropriate.

Each of twelve mutations changes one evaluator predicate in a disposable package
copy. A separate socket-blocked process runs the full corpus against that copy.
The defects are trusting tool success, ignoring claim IDs, normalizing titles,
ignoring duplicates or seed changes, accepting stale grants, ignoring operation
scope, checking expiry at report time, counting replay as a new effect, treating
unknown storage as empty, repairing JSON, and confusing configuration with exercise.

A mutation is detected only by an assertion mismatch. Failed application, syntax,
import or worker errors are reported as errors. A mutant that returns every
expected answer survives. All twelve slots remain visible if the baseline fails.

`comparison.json` is a versioned audit inventory; `report.md` rebuilds from it.
Each variant directory retains raw grades, expected fields, differences, worker
logs and fresh databases. Mutation metadata records the source replacement and
original/changed file hashes. The aggregate fingerprints the package source.
These are local, mutable diagnostic artifacts, not tamper-proof evidence.

The implemented corpus passes the baseline and detects all twelve intended
defects. No production grading change was needed, so historical grades and
versions are preserved. This is finite regression coverage, not a proof of grader
correctness. See PROGRESS.md for final verification.

Learning review: explain one false failure (such as rejecting a historically
authorized write after expiry), one missed defect, and why the reference answer
must be independent of the evaluator being tested.
