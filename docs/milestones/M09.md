# M09 — Crash and restart recovery

The task database can contain a committed task while the run journal still says
an attempt is pending. Recovery reconciles that gap by dispatching the same
operation ID again, subject to the saved budgets.

## Run and resume

```sh
uv run --offline --no-sync aflab reliability run restart-healthy --policy bounded-retry --offline
uv run --offline --no-sync aflab resume runs/YOUR-RUN --offline
```

Resuming a finalized compatible run is a no-op: no inference, task writes or
journal updates. Interrupted compatible process runs continue their saved
conversation. `--live` must match the original mode and checkpoint digest/settings;
there is no fallback. Existing v0.1/M06/M07 runs are refused without modification.

The reproducible crash controller creates two uninterrupted/crash-resume pairs:

```sh
uv run --offline --no-sync python scripts/check_restart.py --offline --output runs/restart-check
```

The output directory must be new. Replace `--offline` with `--live` only for the
explicit four-run local smoke. [Recorded live evidence](M09-live-smoke.md) uses this
controller and retains every original child artifact.

The controller waits for an explicit barrier before dispatch or after task commit,
then sends SIGKILL to its runner and any paused owned worker. It waits for ownership
release before resume. Tests additionally cover attempt reservation, a transaction
before commit, tool-result checkpoint and terminal-result checkpoint.

`reliability run ... --pause-at POINT` is an explicit crash-test interface. It
creates `barrier-ready.json` and waits for an external controller or a
`barrier-release` file. Normal runs do not pause. It is not an automatic crash
policy or a general-purpose debugger.

## Durable transitions

The separate `journal.sqlite3` saves the original configuration, compatibility
fingerprint, full conversation/provider turn, pending tool order and cursor,
operation IDs, attempts, remaining time, fault consumption, terminal result,
evaluation snapshot and artifact-finalization state.

Before inference, it reserves the model-call budget. Before dispatch, it saves the
assistant response, tool request and attempt reservation. Before another model
request, it saves the delivered tool message. Missing uncheckpointed responses
are requested again from the saved conversation, charging both requests; no
identical model response is promised.

Task and run journals are separate transactions. The task layer recovers SQLite's
own transaction journal before independent read-only evaluation. It does not
repair schemas or make the evaluator initialize a database. A protected replay
can recover the original task result without repeating the task effect.

The runner holds an OS lock and passes its descriptor to the worker. An orphaned
worker retains ownership, so a second runner cannot overlap it. This is tested on
the macOS/Linux process model used by CI; Windows is not supported by this runner.

## Budgets and evidence

Resume preserves model/tool counts, attempt ceilings, script cursors and operation
IDs. If an attempt's elapsed time was lost, its full reserved time is charged.
Running out of budget produces an uncertain error, not a fabricated success.

Events use journal sequence numbers across sessions. Monotonic times apply only
within a process session. The wall-clock gap from the last checkpoint includes
unobserved execution as well as downtime; exact crash downtime stays unknown.

An interrupted report write resumes finalization from the saved terminal result
and evaluation. A truncated JSONL projection does not replace journal authority.
Use `aflab diagnose` to inspect projection gaps, imported worker evidence and the
last durable checkpoint.

This protects the synthetic append-only task workflow against selected process
crashes. It does not establish recovery from power loss, corrupted filesystems,
external database edits, or arbitrary remote services. Source/package changes
may make a saved run incompatible; keep the original checkout and locked environment.

The learning review separates recovering a conversation, recovering a task effect,
and producing a supported final claim. None implies the other two.
