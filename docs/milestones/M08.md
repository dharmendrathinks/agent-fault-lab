# M08 — Delays, recovery, and limits

A deadline means the caller has waited long enough. It does not prove the worker
stopped or undo a committed write. M08 makes that distinction observable with a
separate local process for each tool attempt.

## Experiments

```sh
uv run --offline --no-sync aflab reliability compare transient-once --offline
uv run --offline --no-sync aflab reliability compare delay-before-write --offline
uv run --offline --no-sync aflab reliability compare delay-after-commit --offline
```

Each prints a fresh comparison directory. `--live` explicitly selects the approved
local model after preflight. The [live smoke](M08-live-smoke.md) records six runs.

| Comparison | Control | Treatment | Fixed script's expected effect |
|---|---|---|---|
| Transient failure | `process-single` | `bounded-retry` | Zero rows versus one recovered task |
| Delay before write | `observe` | `terminate` | Late write completes versus worker stopped before write |
| Delay after commit | `observe` | `terminate` | One task in both; terminating does not undo it |

The script issues one create and reads a usable result back. A live model chooses
its own calls, including whether to try another logical create. New calls get new
operation IDs; all retries within a call reuse the same ID.

`reliability list` includes healthy execution, one/two/continuous transient failures,
permanent failure, before/after delays, ignored termination, process exit without
a reply, malformed worker output, and restart experiments. Cases declare their
supported policies; unsupported combinations fail before creating run state.

## Limits and ownership

| Limit | Default |
|---|---:|
| Attempt deadline | 2 seconds |
| Operation budget, including waits/cleanup | 8 seconds |
| Maximum protected attempts | 3 |
| Backoff | 100 ms, then 200 ms |
| Termination grace | 500 ms |
| Total run attempts | 18 |
| Injected finite delay | 3 seconds |

The worker validates an allowlisted request, opens its own connection, and blocks
its own sockets. No network tool or inherited SQLite connection is involved.
Transient errors, missing replies and deadlines may retry under `bounded-retry`;
invalid arguments, invalid results, conflicts and permanent failures do not.

`observe` waits beyond the attempt deadline for the finite late result, within the
remaining operation budget. `terminate` requests termination at the deadline,
waits the grace period, then kills if needed. Both wait for confirmed worker exit
before final grading. Keyboard interruption also cleans up the owned worker.

Admission reserves time for cleanup. The implementation still waits for confirmed
exit if OS scheduling or kill completion exceeds that reservation; it never trades
an unknown live writer for an apparently on-time snapshot. This does not cancel an
Ollama server request or an arbitrary external side effect.

## Reading the evidence

```sh
uv run --offline --no-sync aflab diagnose runs/YOUR-COMPARISON/CHILD-RUN
uv run --offline --no-sync aflab report runs/YOUR-COMPARISON --check
```

Look for `deadline_expired`, `cancellation_requested`, optional `kill_requested`,
`worker_exit_confirmed`, and `late_response`. Worker evidence records actual
activation and storage receipts separately. The evaluator uses its own read-only
SQL path after worker exit. Parent collection order does not prove which event
won a close commit/cancellation race; the final row count remains inspectable.

Offline tests cover each fault, exhausted budgets, fake-time backoff, ignored
termination, actual commit/cancel races, and socket blocking in the child itself.
These tests demonstrate the mechanism, not model reliability. Review why a
completed task can coexist with a delivered timeout and a false non-completion claim.
