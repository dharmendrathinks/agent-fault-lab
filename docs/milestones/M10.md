# M10 — Diagnostic traces

`aflab diagnose` explains a saved run without calling a model, executing a tool,
opening task storage for grading, or changing the evidence bundle.

```sh
uv run --offline --no-sync aflab diagnose runs/YOUR-RUN
uv run --offline --no-sync aflab diagnose runs/YOUR-RUN --format json
```

It reports the requested task and configured policy, observed fault activations,
attempts, actual replies, contract failures, retry decisions, deadlines,
cancellation, the last checkpoint, available independent evaluation, terminal
claim support and unresolved gaps. Each timeline entry references a journal row
or original JSONL line; worker entries also name their source file and line.
Markdown previews long details; JSON retains the full diagnostic detail.

New process runs have standardized run/session/call/operation/attempt identifiers.
The journal sequence is authoritative across resumes. The JSONL file is a readable
projection, and differences are reported explicitly. Worker timing remains local
to that process; collection after exit does not prove cross-process event ordering.

Legacy M06/M07 traces remain supported in their original schema. They are not
retroactively assigned missing run/session identities. Malformed or unsupported
evidence produces explicit gaps. A missing independent evaluation means unknown
task outcome. An intact saved evaluation can still establish task state when the
causal timeline is incomplete; those conclusions remain separate.

## Required bundles

Offline regressions and the existing live artifacts cover:

| Bundle | Evidence to inspect |
|---|---|
| Malformed response after write | Rejected contract plus independently stored task |
| Unprotected lost-reply retry | Two committed rows despite one logical call |
| Protected lost-reply retry | Stable operation ID and original result replay |
| Deadline before write | Deadline, exit confirmation and empty task state |
| Cancellation after commit | Task remains despite the delivered error |
| Crash after commit and resume | Same operation ID, charged reservation, one task |
| Missing/inconsistent artifacts | Explicit unknown outcome or causal-history gaps |

Golden expectations check event order, source references and unknown conclusions.
Other tests exercise conflicting timestamps, partial projection, unsupported schema,
changed evaluation and read-only behavior. M10 adds no live inference.

## Independent reviewer handoff

Give another engineer a synthetic bundle and these commands, without the development
conversation. Ask them to identify the trigger, stored effect, safeguard behavior,
and remaining uncertainty using only the files. The supplied bundle should contain
manifest, journal where applicable, trace and worker traces, result, evaluation,
observation and report. Task storage may be included for manual inspection, but
`diagnose` itself uses only the saved evaluation.

| Review record | Status |
|---|---|
| Implementation self-review and automated checks | Recorded in PROGRESS.md |
| Review completion | Confirmed by the maintainer on 2026-09-07; stable promotion authorized |
| Independent reviewer identity | Not supplied in the confirmation |
| Reviewer's explanation of the failure | Detailed notes not supplied |
| Ambiguities and resulting documentation fixes | No additional changes requested with confirmation |

The review gate is closed on the maintainer's explicit confirmation, recorded in
PROGRESS.md. The implementation agent did not perform or observe that human review.
Passing tests alone is not evidence that another engineer understood the bundle.
Saved reports are reproducible presentations, not authenticated claims.
