# M17 — External failure reproduction

Status: implemented locally, unreleased. Learning acceptance and M18 independent
review remain pending. The stable release remains v0.4.0.

## What this teaches

A framework can finish its call while an application effect is missing. We test
that distinction without a model: a graph should save exactly one task. Its state
and pending-work list describe framework execution; independent SQL establishes
whether the task exists. Neither is a model completion claim.

The case reduces [LangGraph issue #8834](https://github.com/langchain-ai/langgraph/issues/8834).
It compares a transient work-node failure with one in the conditional router
after work returns a state update. See the
[standalone reproduction and attribution](../../reproductions/langgraph-8834/README.md).
The reported problem predates this lab case; we do not claim discovery or upstream
confirmation of a source-level root cause.

## Try it

Use this development checkout, not the v0.4.0 tag. Install root dependencies
with `uv sync --locked --all-groups`, then:

```sh
make external-setup
uv run --offline --no-sync aflab external list
uv run --offline --no-sync aflab external doctor langgraph-router-resume
uv run --offline --no-sync aflab external run langgraph-router-resume --output runs/external-case
uv run --offline --no-sync aflab report runs/external-case --check
```

Open `runs/external-case/report.md`. Each run needs a fresh directory. Setup
installs Python dependencies into a separate pinned environment; execution needs
no network, model or credentials. `make external-check` runs the real matrix and
asserts the controls and known pinned-version symptom. Root unit tests use labeled
fixtures without this environment. Wheels can list cases and read saved reports;
execution requires a source checkout and explicit setup.

## Fixed experiment

| Condition | Injection | Required application effect |
|---|---|---|
| Healthy | None | One task after initial call; no extra task after resume |
| Node failure | Before work returns state | One task after resume |
| Router failure | After work returns, before routing succeeds | One task after resume, or an exposed unresolved execution failure |

Each condition runs three times with InMemorySaver in one process, SqliteSaver in
one process, and SqliteSaver across two processes: **27 lifecycles, 54 invocations**.
Each lifecycle owns fresh task/checkpoint databases and a unique thread ID. Only
the initial phase can activate the fault. Resume calls `invoke(None, config)`
with the same thread ID. The sink has no deduplication safeguard, so repeated
execution remains visible as extra rows rather than being hidden.

The controller inspects SQLite read-only after the initial observation, before
allowing same-process resume or starting a fresh worker. It inspects again after
resume and worker cleanup. Workers commit writes before returning and record
work/router/sink events. Sink calls are graph executions, not model tools.

## Reading the evidence

`comparison.json` is the versioned `external-reproduction` artifact: full ordered
inventory, Python/platform and installed dependencies, worker/lock/harness hashes,
source reference, invocation snapshots, counts, timings, fault activation and
independent evaluations. Each lifecycle also retains `events.jsonl`, invocation
and evaluation JSON beside its databases (memory mode has no checkpoint file).
All runtime artifacts stay under ignored `runs/`.

- **Harness:** completed, failed, interrupted or unstarted. An injected initial
  exception is experimental evidence. An exposed resume exception also remains a
  framework observation; missing/malformed output or unreadable SQL is a harness failure.
- **Symptom:** reproduced requires an exercised router fault, normal resume with
  `value=1`, no pending work, no sink calls and a verified empty task table. Other
  complete outcomes are not reproduced; incomplete evidence is inconclusive.
- **Task:** completed requires one exact-title row with a usable ID. Missing,
  duplicate or wrong rows mean not completed. Uninspectable storage is unknown.
- **Model claim:** absent; model calls are zero. No model false-success rate is scored.

A captured reproduction exits 0; harness failure exits 2; interruption exits 130.
The sequential matrix has a 300-second budget and each worker a 30-second limit.
Cleanup may add a small bounded wait. Reservations are saved before spawning, so
failed/interrupted/unstarted attempts remain visible. There is no automatic retry
or matrix continuation. An uncatchable controller exit can leave its last reservation
marked interrupted and raw evidence newer than the summary; that is not a completed
result. Workers inherit the run lock and have their own alarm. Saved reports read
validated captured JSON only, never current databases or the framework.

## Local observation and limits

The initial macOS ARM64 matrix reproduced the symptom in all **9 router-failure
lifecycles**, across all three modes. All **18 controls** saved exactly one task,
without duplication on resume. Final verification paths and hashes are recorded
in [PROGRESS.md](../../PROGRESS.md). CI is configured for Ubuntu 24.04/macOS 14;
local results do not imply those jobs ran on this change.

This uses LangGraph 1.2.11 and SQLite saver 3.1.1, with a separate full lock. It
is a package-version reproduction, not a tested upstream patch. Other versions,
async execution, arbitrary graphs, abrupt crashes, power loss and external effects
are outside its evidence. Python socket blocking is not an OS sandbox. Local
evidence is mutable and trusted, not authenticated by an independent party.

## Learning checkpoint and next step

Review one lifecycle from each condition. Explain why normal resume and an empty
pending list do not establish that the sink saved a task. Distinguish the application's
task contract from an upstream-confirmed framework guarantee. Human learning
acceptance is separate from passing tests.

M18 will prepare a shareable synthetic package, obtain one outside engineer's
reproduction, address feedback and prepare a focused upstream contribution. A merge
is optional; independent review is required. No export command, outreach, upstream
fix or release is part of M17. See the
