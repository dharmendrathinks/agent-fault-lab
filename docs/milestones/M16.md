# M16 — Runtime transfer

Available in v0.4.0. Learning acceptance and the
live comparison remain pending. This experiment asks which checks survive when
a different runtime controls the order of model and tool execution.

## Setup and bounded runs

```sh
make scanner-setup runtime-setup
uv run --offline --no-sync aflab runtime doctor langgraph
uv run --offline --no-sync aflab runtime run langgraph approved --offline --output runs/graph-approved
uv run --offline --no-sync aflab runtime run native approved --offline --output runs/native-approved
uv run --offline --no-sync aflab report runs/graph-approved --check
make runtime-check
```

Setup installs Python dependencies, without downloading a model or running
inference. LangGraph 1.2.11 is pinned in `integrations/langgraph/uv.lock`, with
Python 3.12 and the local project installed in that environment. Root runtime
dependencies remain unchanged. Missing integration setup is an explicit error.
Both compared runtimes launch in this same environment so provider dependencies
also match. Doctor records installed versions and the integration lock digest.

The real `StateGraph` has model, tools and terminal nodes connected by conditional
edges. Each model node requests one turn; each tool node processes one pending
call. The graph never invokes the native orchestration loop. Both runtimes share
individual operations for validation, permissions, context refresh, exact input,
stable operation IDs, evidence and budgets. The independent SQL grader is shared.
See the upstream [graph API](https://docs.langchain.com/oss/python/langgraph/graph-api).

There are no implicit retries, output repair, parallel tool calls, graph caching,
checkpoint resumption, hosted inference or telemetry. The model, prompt and tools
are unchanged. Limits remain six model requests and six tool requests; graph
recursion is capped separately. The worker has a 450-second physical deadline and
shares the study process group, so the remaining study deadline also applies.
Committed writes survive termination; stopping Ollama generation is not guaranteed.

## Matched pilot

```sh
uv run --offline --no-sync aflab study plan runtime --output runs/runtime-plan.json
uv run --offline --no-sync aflab study run runs/runtime-plan.json --offline --output runs/runtime-study
uv run --offline --no-sync aflab report runs/runtime-study --check
```

The default design is 24 runs: native/LangGraph × three repetitions × four cases:

| Case | Fixed policy |
| --- | --- |
| `approved` | Scoped approval, permission enforcement |
| `rejected` | Rejected proposal, permission enforcement |
| `injection-override` | Tool-response delivery, permission enforcement |
| `memory-stale-title` | Authoritative refresh, permission enforcement |

All use real static SkillSpector and scan enforcement. Cases are shuffled with
seed 42 and runtime order alternates by repetition. A 30-minute active budget
preserves partial/failed/unstarted slots. `--live` selects the already approved
local checkpoint explicitly; planning and offline execution never infer. Offline
turns are scripted and establish no framework or model effectiveness claim.

`runtime-manifest.json` marks the run before execution. `runtime.json` records
runtime identity, graph-node sequence, duration and the captured independent
evaluation. Boundary traces and `evaluation.json` remain available. Saved reports
validate that both evidence records agree. Study children seal these runtime
records and use the same per-scenario reporting and conservative recovery rules.

Manual approval, resuming a child, and crash/restart parity are unsupported and
rejected. Study resume may continue previously unstarted slots; it never resumes
or repeats an attempted runtime child. A wheel alone has no integration environment;
use the source checkout for the explicitly installed runtime.

`make runtime-check` executes actual graph cases with sockets blocked and tests
malformed/truncated claims, invalid tools, call budgets and provider errors.
It replaces the native loop with a failing stub during graph runs to catch a
hidden delegation to the original loop. CI runs this check on Ubuntu and macOS.

Learning review: explain which contracts transferred, what the graph actually
controls, and why shared tool operations plus offline parity do not establish
independent real-world reliability or crash recovery parity.
