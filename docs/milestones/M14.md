# M14 — Repeated comparisons

Available in v0.4.0. Learning review
is pending. See [PROGRESS.md](../../PROGRESS.md) for actual verification and live
evidence; implemented commands are not a claim that the complete pilot was run.
The [initial semantic probes](M14-semantic-probes.md) both timed out without a
complete classification; semantic comparison feasibility remains unvalidated.

A study fixes its comparison conditions before it starts. Each repetition gives
each policy the same case, settings and limits. Failed or interrupted executions
stay in the inventory, so removing difficult runs cannot improve the result.

## Run a small offline study

From the v0.4.0 checkout and its locked Python 3.12 uv environment:

```sh
mkdir -p runs
uv run --offline --no-sync aflab study list
uv run --offline --no-sync aflab study plan claims --repetitions 3 --output runs/claims-plan.json
uv run --offline --no-sync aflab study run runs/claims-plan.json --offline --output runs/claims-study
uv run --offline --no-sync aflab report runs/claims-study --check
uv run --offline --no-sync aflab study resume runs/claims-study --offline
```

Use new paths for a new study. `plan` refuses to overwrite a file. `run` refuses
to reuse a directory. Reports rebuild from validated captured JSON, without
re-querying storage or invoking a scanner or model. Resume verifies the original
manifest and actual source/lock fingerprints; finish an old study with its original
checkout. Interrupted started slots are preserved, never replayed automatically.

| Preset | Matched agent/scanner runs at 3 repetitions | Additional executions |
|---|---:|---|
| `claims` | 12 agent runs | 12 ordinary workflow companions |
| `retries` | 12 agent runs | 12 ordinary workflow companions |
| `approvals` | 12 agent runs | None |
| `injection` | 12 agent runs | None |
| `context` | 6 agent runs | None |
| `semantic-admission` | 12 agent runs | 2 semantic feasibility probes |
| `scanner` | 48 scans | 2 semantic feasibility probes |

The default budget is 1,800 active seconds per study, including its probes. Use
`--budget-seconds` when planning to select a shorter budget; it cannot exceed
1,800. The default ordering seed is 42. It controls shuffled case blocks, not
model determinism; policy order alternates across repetitions.

Offline agents are programmed scripts. The first five presets retain real static
SkillSpector for boundary cases, requiring `make scanner-setup`. Both profiles in
offline semantic presets use an explicit scanner double. Those runs test schedules,
admission/report wiring and recovery only; they cannot measure scanner detection.

## Ordinary workflow companion

This participant calls create, reads the exact returned ID, checks its matching
title/ID and reports. It does not query SQLite directly or inspect fault labels.
It uses the same fault and execution policy, with zero model requests. The
independent evaluator checks the whole database: one correct read can still miss
an extra task created by an unprotected retry after a lost reply. Workflow runs
are labeled separately and excluded from the paired agent contrast.

## Explicit local inference and semantic scanning

`--live` is the explicit local-inference mode. `plan`, default tests and package
checks never start inference. The plan freezes the existing Qwen3 Instruct tag,
approved digest and settings. Preflight rejects changed identity, cloud-enabled
Ollama or missing capabilities; nothing downloads a model or changes the daemon.

```sh
make scanner-setup
uv run --offline --no-sync aflab doctor
uv run --offline --no-sync aflab study plan semantic-admission --output runs/semantic-plan.json
uv run --offline --no-sync aflab study run runs/semantic-plan.json --live --output runs/semantic-study
```

SkillSpector stays pinned in its separate environment. The semantic profile uses
upstream model analyzers and meta-analysis where applicable. Its socket boundary
allows only the study-owned loopback gateway. The gateway accepts text chat
completions, forwards them through native Ollama with `think=false`, temperature
0, context 4,096, and at most 1,024 output tokens. JSON-schema requests are mapped
explicitly; forced tool selection, tool histories, streaming, other models and
other endpoints are rejected. No hosted fallback or implicit request repair.

Each scan allows 180 seconds and at most 12 physical model requests, each in a
separate supervised process with at most 60 seconds. Raw scanner output and
gateway evidence are bounded; errors or truncation fail admission. The upstream
model registry is supplied through its supported override with verified checkpoint
capacity, avoiding the unknown-model 128k fallback. Requested and effective
settings, physical requests, usage and transport failures remain in private evidence.

Two fresh probes precede each live semantic study: one benign and one attack.
Both must produce complete inspectable results within limits. Their classification
need not be correct. A failed probe leaves the remaining slots unstarted; resume
does not tune the model, skip the gate or replay the failed probe. Start a new
study after a reviewed implementation/configuration change. Probe rows are distinct
from benchmark participants. Each later observation gets a fresh scan.

## Read the evidence

`plan.json` records the frozen design. `comparison.json` retains every scheduled
slot, active-time accounting and sealed child observations. Every child has its own
directory, evaluator output and traces; `study-child.json` seals the child only
after grading. Unsealed failures retain a read-only storage inspection when possible.
Semantic v2 sidecars record the profile and gateway; the normalized v1 admission
projection keeps existing boundary/report readers compatible.

The report separates execution, storage, report validity and claim support. It
shows assessable completion-claim denominators, failures, unstarted cells, paired
exclusions and duration variation. Conditional Wilson intervals assume independent
trials; this small repeated fixture pilot does not establish that assumption or
general security accuracy. Missing usage is unknown, not free inference.

Workers inherit the study lock and have their own deadline. After a controller
crash, recovery conservatively charges the reserved time when exact timing is
unknown. This may end a study early. Killing a process cannot undo an already
committed task or guarantee that Ollama stops a submitted generation. Python socket
restrictions are not an operating-system sandbox for untrusted dependencies.

For the pending learning review, inspect one paired scenario, a duplicate effect missed by read-back,
and a partial run. Explain what improved, what cost extra and what the evidence
cannot establish. Technical checks and learning acceptance are separate.
